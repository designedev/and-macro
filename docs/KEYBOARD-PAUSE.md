# 키보드 창으로 인한 종료 수정 — 0.7.1

2026-10-04 실제 Galaxy에서 14:36:29 키보드 창이 나타난 직후 `SESSION_STOP`이 기록되었고 밝기는 복구되었습니다. 앱 프로세스는 살아 있어 앱 충돌이 아니라 창 검증에 따른 정상 종료였습니다. 사용자도 게임에서 실제 키보드가 열렸다고 확인했습니다. 기존 정책은 입력기 창을 위치·포커스와 무관하게 차단했습니다.

실행 중 대상 앱 위의 입력기 창이 유효한 크기로 사용 가능한 화면 영역에 겹치면 클릭을 대기합니다. 입력기가 활성 창을 차지하면 뒤의 포커스된 앱을 확인하며, 대상 패키지와 창 ID가 일치할 때만 키보드 대기를 허용합니다. 다른 앱·검증되지 않은 창의 차단 규칙은 유지합니다. 화면 밖의 입력기 창과 앱보다 아래에 있는 입력기 창은 대기 대상에서 제외합니다.

키보드를 닫은 뒤 동일 앱·창을 검증하고 새 프레임을 인식합니다. 알림과 동일한 일시 대기 예외를 사용하여 연속 인식 오류를 누적하지 않고, 기존 엔진의 클릭 전 대기 초기화·개별 클릭 간격 유지 동작을 적용합니다. 시작·인식 테스트·이미지 등록은 키보드를 닫아야 합니다. 이미 전달된 제스처의 취소는 보장하지 않습니다. 로그는 `KEYBOARD_WAIT`·`KEYBOARD_RESUMED`이며 키보드 입력 내용은 읽거나 기록하지 않습니다.

## 검증

- 단위 테스트: 보이는 키보드, 실제 단말기에서 관찰한 화면 밖 애니메이션 좌표, 빈 영역·아래 계층 입력기 분류. 기존 일시 대기·재개·취소·클릭 전 대기·간격 테스트 유지.
- Android 테스트: 에뮬레이터에서 실제 키보드 표시와 숨기기, 원래 앱·창 복귀를 공유 창 어댑터와 정책으로 확인.
- 전체 매크로 캡처·터치 흐름의 실제 Galaxy 게임 키보드 검증은 사용자 재시험이 필요합니다.

## 밝기 조사와의 관계

같은 세션에서 최저 밝기를 적용한 뒤 인식과 클릭이 성공한 로그가 있습니다. 이번 오버레이 종료 원인은 키보드 차단으로 확인되었습니다. 화면 밝기가 모든 기기의 캡처에 영향을 주지 않는다고 단정하거나, 키보드가 열리기 전에 발생한 모든 조건 미검출을 이 원인으로 설명하지는 않습니다. 장시간 인식 실패가 별도로 재현되면 추가 조사가 필요합니다.
