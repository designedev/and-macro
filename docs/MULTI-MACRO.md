# 0.4.0 — 다중 매크로와 드래그 우선순위

검증일: 2026-10-03, Asia/Seoul.

## 확정한 동작

사용자는 여러 매크로를 함께 활성화하고 드래그로 클릭 우선순위를 지정하도록 요청했습니다. 추가로 확인한 실행 규칙은 ‘클릭 가능한 조건 중 목록 위쪽부터 실행하고 상위 매크로가 대기 중이거나 조건이 없으면 다음 순위 실행’입니다. 매크로별 간격은 독립 적용합니다. 원래 첨부 명세의 동시 실행 하나 제한은 이 새 요청에 따라 확장했습니다.

## 구현

- 체크 상태와 우선순위를 저장합니다. 오른쪽 드래그 핸들, 현재 순위, 조건 문구, 선택한 매크로 실행 버튼을 제공합니다.
- 드래그 중 카드가 손의 이동을 따라가며 목록 끝에서는 자동 스크롤합니다. 드래그 취소 시 순서를 되돌리고 손을 놓으면 한 트랜잭션으로 전체 순위를 저장합니다. 접근성 사용자 동작으로 순위 올리기/내리기도 제공합니다.
- 기존 단독 실행과 클릭 없는 인식 테스트는 유지합니다. 인식 테스트는 한 매크로씩 진행합니다.
- 실행 그룹에 단일 MediaProjection·가상 디스플레이·캡처 소스·터치 실행기를 사용합니다. 같은 검색 영역의 OCR은 한 번 읽고 각 문구·일치 방식에 적용합니다. 이미지·문구 조건을 함께 사용할 수 있습니다.
- 다중 실행 엔진은 매크로별 클릭 간격, 클릭 후 대기, 클릭 전 대기 시간을 관리합니다. 상위 조건의 대기·미검출·복수 후보가 다른 조건을 막지 않습니다.
- 매번 클릭 가능한 유일 후보 중 우선순위를 적용합니다. 인식 중 상위 간격이 끝나면 상위 조건을 새 프레임에 포함해 다시 확인합니다.
- 제스처는 순차 전달합니다. 클릭 후 남은 좌표를 예약하지 않고 새 프레임을 얻습니다. 정지·창 전환·캡처 종료·회전·잠금·접근성 해제와 프레임 1초 제한은 유지합니다.
- 연속 인식 오류 3회면 그룹 전체를 정지합니다. 실행 중 체크·순서·설정 수정과 삭제는 차단합니다.
- 새 매크로는 목록 끝에 추가합니다. 편집으로 순위와 체크 상태가 바뀌지 않으며 삭제 후 순위 번호를 정리합니다.

## 데이터 업그레이드

Room version 1 → 2 마이그레이션에서 priority와 selected 열만 추가합니다. 기존 이름·문구·간격·검색 영역·이미지 참조와 호환용 targetPackage 열을 유지합니다. 기존의 최신 수정순 목록을 초기 우선순위로 보존하며 체크는 해제 상태로 초기화합니다. 앱 삭제, 데이터 재생성, destructive migration을 사용하지 않습니다. 이후 순서와 체크 상태는 앱 재시작 후에도 유지되며 자동으로 실행하지 않습니다.

## 검증 범위

최종 테스트 및 단말기 설치 결과는 outputs/test-results.json과 outputs/emulator-multi-tests.txt에 기록합니다. 단위 테스트는 우선순위, 독립적인 간격·전후 대기, 새 프레임 재인식, 제스처 취소, 창 무효화, 오래된 프레임, 정지 및 3회 오류를 확인합니다. 에뮬레이터에서는 실제 드래그·스크롤·취소·재시작 저장, version-1 DB 데이터 및 이미지 참조 보존, 한국어/영어 OCR, 이미지·문구 혼합 인식을 검증합니다.

실기기의 이전 0.3.1 단독 게임 동작 확인과 0.4.0의 다중 게임 동작 확인은 별개의 검증입니다. 사용자는 0.4.0의 다중 실행·드래그 우선순위·개별 간격을 시험한 뒤 “원하는대로 동작한다”고 확인했습니다. 실제 단말기의 게임 화면을 파일로 수집하지 않습니다. 이후 보고된 게임 부스터 터치 방지 시 종료 문제는 [별도 조사 기록](GALAXY-GAME-DIMMING.md)으로 구분합니다.

연결된 SM_S948N(Android 17 / API 37)에 같은 debug 키의 0.4.0을 덮어 설치했습니다. 단말기 versionCode 5 / versionName 0.4.0과 MainActivity 시작을 확인했습니다. 기존 앱을 삭제하거나 데이터를 재생성하지 않았습니다. 실제 게임의 다중 실행 결과는 사용자가 정상 동작을 확인했습니다.
