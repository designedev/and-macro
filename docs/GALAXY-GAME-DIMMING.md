# 갤럭시 게임 화면 어두워짐과 매크로 종료 조사

조사일: 2026-10-03. 앱 0.4.0, SM_S948N, Android 17 / API 37.

후속 사용자 확인: 자동 터치 방지를 직접 끈 뒤 문제가 해결되었습니다. 실행 중 화면을 어둡게 하는 새 기능은 [0.5.0 밝기·오버레이 기록](BRIGHTNESS-OVERLAY.md)으로 구분합니다.

## 결론과 확인 범위

사용자는 게임 화면이 어두워질 때 자물쇠가 나타나고 매크로 오버레이가 사라진다고 보고했습니다. 삼성 공식 설명에 따르면 게임 부스터의 터치 방지는 게임을 켜둔 상태에서 화면 터치를 막으며 자동 적용 시간과 밝기를 조절하는 기능입니다. 이 설명과 사용자 증상을 함께 보면 자동 터치 방지가 원인일 가능성이 높습니다. 배터리 최적화 예외는 이 터치 차단을 해제하는 기능이 아닙니다.

앱 자체 Logcat에서 14:47:06 실행 시작, 제스처 완료, 계속된 두 조건의 인식, 14:49:05의 아래 종료 이유를 확인했습니다.

> 화면 또는 활성 창이 바뀌었습니다. 수동 재시작이 필요합니다.

진단 원본: `outputs/device-game-dimming-diagnostic.txt`. OCR 원문이나 게임 화면 이미지는 수집하지 않았습니다.

조회 시 앱 프로세스 PID 11386은 살아 있었고 CaptureService는 종료된 상태였습니다. 현재 화면은 Awake, 충전 중, device idle의 일반·light 상태는 ACTIVE였습니다. 앱 standby bucket은 10(active), RUN_ANY_IN_BACKGROUND는 기본 allow입니다. Android deviceidle 예외 목록에는 앱이 조회되지 않았습니다. 삼성 자체 절전 목록의 등록 여부는 이 조회만으로 확정하지 않습니다.

이 상태 값들은 종료 시점 이후 조회 결과입니다. 따라서 종료 순간에 터치 방지 창이 어떤 접근성 타입으로 나타났는지까지 입증하지는 않습니다. 다만 앱 프로세스를 잃은 사건이 아니라 앱 코드의 세션 검증에 따라 캡처·오버레이를 정리한 사건이라는 로그 근거가 있습니다. 실제 화면 잠금·절전 종료를 이번 사건의 원인으로 단정하지 않습니다.

## 권장 설정과 재확인

1. 게임 실행 중 게임 부스터를 열고 설정으로 이동합니다. ‘터치 방지 적용 시간’ 또는 ‘자동 터치 방지’에서 자동 적용을 끄는 선택을 사용합니다. 모델·One UI·게임 부스터 버전에 따라 메뉴 이름과 위치가 다릅니다. 터치 방지가 이미 나타났다면 자물쇠를 드래그해 해제합니다.
2. 앱에서 선택한 매크로 실행과 캡처 동의를 다시 진행하고 게임에서 현재 앱 실행을 누릅니다. 기존 터치 방지 적용 시간을 넘겨 관찰하여 오버레이와 조건 클릭이 유지되는지 확인합니다. 이 설정 변경 후의 재현 결과는 아직 확인하지 않았습니다.
3. 별도로 화면이 실제로 꺼지는 경우 설정 → 디스플레이 → 화면 자동 꺼짐 시간을 확인합니다. 게임 부스터 자동 터치 방지와 기기 화면 꺼짐 시간은 서로 다른 설정입니다.

‘터치 방지 사용 중 절전’은 게임 프레임 속도를 낮추는 옵션입니다. 이것만 꺼도 터치 방지 자체는 남으므로 우선 자동 터치 방지의 적용을 해제해야 합니다.

## 배터리 예외와의 관계

삼성 앱 절전·초절전은 백그라운드 실행에 제한을 줄 수 있습니다. 향후 별도의 백그라운드 중단 문제가 나타난다면 설정 → 배터리(또는 디바이스 케어 → 배터리) → 백그라운드 사용 제한에서 화면 매크로를 절전·초절전 목록에서 빼고 ‘절전 상태로 전환하지 않을 앱’에 추가하는 방법을 사용할 수 있습니다. 앱 정보 → 배터리의 ‘제한 없음’ 옵션이 제공되는 기기에서는 그 옵션도 확인할 수 있습니다. Android 최적화 예외와 삼성 자동 절전 목록은 기기 UI에 따라 보이는 항목이 다릅니다.

현재 앱은 MediaProjection 유형의 foreground service를 사용합니다. 표준 Android의 App Standby는 foreground service를 실행하는 앱을 일반적인 미사용 앱처럼 판정하지 않습니다. 삼성도 One UI 6 이후 Android의 새 foreground service 정책에 맞게 구현한 서비스의 동작을 보장한다고 설명합니다. 따라서 실행 중이라는 이유만으로 배터리 예외가 반드시 필요하다고 판단하지 않습니다.

실제 기기 잠금은 별개입니다. Android 15 QPR1 이상에서는 화면을 잠그면 MediaProjection이 시스템에 의해 종료됩니다. 배터리 예외나 CPU partial wake lock으로 이미 종료된 캡처를 유지할 수 없습니다. 현재 코드도 화면 꺼짐·기기 잠금·활성 창 변경 시 세션을 종료하고 수동 재시작하도록 구현되어 있습니다.

## 앱 수정 판단

이번 조사에서는 코드와 기기 설정을 변경하지 않았습니다. 권장 설정으로 먼저 재확인한 뒤, 실행 중 화면 유지 또는 앱 내 배터리 설정 안내가 추가로 필요한지 결정하는 순서가 적절합니다. 임의의 잠금 화면을 계속 클릭하도록 창 검증을 제거하는 방식은 조건 인식과 실제 클릭 대상을 일치시키지 못하므로 권장하지 않습니다.

짧게 표시되는 Toast와 별개로 현재 앱은 종료 이유를 RuntimeStore.status에 남겨 메인 화면 상단에 표시합니다. 새 실행이나 프로세스 종료 전에는 앱으로 돌아가 읽을 수 있습니다. 프로세스 재시작 후에도 보존하는 종료 이력은 현재 구현되어 있지 않습니다.
