# 설치와 사용

## 설치

1. [README의 빌드 안내](../README.md)를 따라 debug APK를 생성하고 Android 16 이상, 64비트 단말기에 `app/build/outputs/apk/debug/app-debug.apk`를 복사합니다. 로컬 전달용 사본은 `outputs/screen-macro-debug.apk`이며 APK는 Git 저장소에 포함하지 않습니다.
2. 파일을 열고 해당 파일 관리 앱의 ‘이 출처의 앱 설치 허용’을 확인하여 설치합니다.
3. 앱 이름은 ‘AUTO’, 패키지는 `com.personal.screenmacro`입니다.
4. 특정 게임이나 앱의 설치는 요구하지 않습니다. 실행할 대상 앱으로 직접 이동하여 오버레이의 실행 버튼을 누릅니다.

이 APK는 debug 키로 서명된 검증용 빌드입니다. 개인용 release 키로 전환할 때에는 서명이 달라 재설치가 필요할 수 있으며 삭제하면 설정과 이미지가 사라집니다. 검증한 기기와 OS만 검증 완료로 표시합니다.

## 권한

- 앱의 사람 모양 접근성 아이콘 → 설치된 앱/다운로드한 앱 → AUTO → 사용 활성화.
- 설정이 제한되면 OS 설정 → 앱 → AUTO → 우측 메뉴 → ‘제한된 설정 허용’을 확인합니다. 제조사에 따라 경로가 다릅니다.
- 종 모양 알림 아이콘을 눌러 권한을 허용하면 실행 중 정지 알림이 표시됩니다. 거부해도 포그라운드 서비스를 일괄 금지하지 않으며 접근성 오버레이 정지를 사용합니다.
- 해 모양 밝기 아이콘의 설정 화면에서 ‘시스템 설정 변경’을 허용합니다. 매크로 실제 실행 시 최저 밝기를 적용하고 종료 시 밝기와 자동 밝기 모드를 복구합니다. 인식 테스트·이미지 등록에서는 밝기를 변경하지 않습니다.
- 매 세션마다 전체 화면 캡처 동의를 요청합니다. 접근성이나 캡처 동의를 앱이 자동 승인하지 않습니다.

## 텍스트 매크로

1. ‘새 매크로’ → 이름 → ‘문구 OCR’ → 찾을 문구를 입력합니다.
2. 기본은 줄 전체의 정확 일치입니다. 양끝 공백 제거와 Unicode NFC 정규화를 적용합니다. 필요하면 포함 일치·영어 대소문자 무시를 켭니다.
3. 클릭 간격은 기본 3.0초, 최소 1.0초, 0.1초 단위입니다. 전후 대기는 기본 0초입니다. 시간의 상한은 24시간입니다.
4. 검색 범위 기본값은 전체 화면입니다. 필요할 때 ‘검색 범위 드래그 지정 (선택)’으로 캡처 화면에서 범위를 선택합니다. 숫자 좌표 입력은 없으며 ‘전체 화면으로 변경’으로 제한을 해제할 수 있습니다.
5. 저장 → ‘인식 테스트’ → 화면 캡처 동의 → 직접 대상 앱으로 이동 → 오버레이의 ‘현재 앱에서 인식 테스트’를 누릅니다.
6. 결과 화면에서 검출 상자·중심점·처리 시간·읽은 문구 목록을 확인합니다. 테스트는 실제 터치를 전달하지 않습니다. 포함 일치는 찾은 부분 문자열이 들어 있는 **줄 전체의 중심**을 표시합니다.
7. 위치가 맞으면 목록에서 ‘시작’ → 동의 → 대상 앱 이동 → 오버레이에 ‘준비 완료’가 표시되고 버튼이 활성화된 뒤 ‘현재 앱에서 실행’으로 감시를 시작합니다.

## 이미지 매크로

1. ‘새 매크로’ → ‘이미지’ → ‘대상 앱 화면에서 이미지·검색 영역 등록’ → 전체 화면 캡처 동의.
2. 대상 앱으로 이동한 뒤 오버레이의 ‘기준 이미지 캡처’를 누릅니다.
3. 오버레이를 숨긴 이후 수집한 한 프레임이 앱의 자르기 화면에 나타납니다.
4. ‘기준 이미지’를 선택해 요소 영역을 드래그합니다. ‘검색 영역’을 선택해 해당 요소가 있을 영역을 드래그하거나 전체 화면을 유지합니다.
5. ‘영역 적용’ → 임계값과 간격 설정 → ‘저장’. 단색·특징 부족, 12px 미만, 검색 영역보다 큰 이미지는 거부합니다.
6. 인식 테스트로 위치를 확인한 뒤 실행합니다. 회전·해상도·화면 배율·대상 앱 UI 크기가 바뀌면 재등록합니다.

임계값 기본 0.90은 OpenCV의 정규화 유사도 점수이며 성공 확률이 아닙니다. 별개의 후보가 둘 이상이면 클릭하지 않습니다.

## 실행과 정지

- 체크한 여러 매크로를 하나의 캡처 세션에서 함께 감시할 수 있습니다. 제스처는 한 번에 하나만 전달합니다. 실행 중 설정 수정·삭제·체크·우선순위 변경은 차단합니다.
- 최소 간격은 직전 터치 전달 시각을 기준으로 계산합니다. 제스처가 취소되어도 즉시 재시도하지 않습니다. 클릭 후 대기는 제스처 종료 시각부터 계산합니다.
- 클릭 전 대기가 있으면 기다린 후 새 프레임에서 다시 인식합니다.
- 오버레이 ‘정지’, 앱 ‘정지’, 알림 ‘정지’, OS 화면 공유 종료로 세션을 끝낼 수 있습니다.
- 다른 앱·알 수 없는 활성 시스템 창, 화면 잠금·꺼짐, 회전·해상도 변경, 접근성 해제 또는 캡처 종료는 자동 재시작하지 않습니다. 대상 앱으로 돌아와 수동으로 다시 동의하고 시작합니다.
- 화면 확대가 적용되면 좌표 안전성을 위해 실행하지 않습니다. Android 접근성 확대를 해제한 뒤 다시 시도하세요.
- 이미 OS에 전달한 터치 한 건은 정지로 되돌릴 수 없습니다.

## 제한과 문제 해결

0.3.1은 연결된 SM_S948N(Android 17)의 마비노기 모바일에서 사용자 정상 동작 확인과 OCR·제스처 완료 로그를 확인했습니다. 다른 기기·앱·게임 화면의 호환성은 별도 검증이 필요합니다. 접근성 루트·활성 창 정보를 확인할 수 없으면 클릭하지 않습니다. 전체 화면 캡처 크기가 확정되지 않거나 보호된 화면에서 캡처가 실패해도 클릭하지 않습니다. 검은 화면만으로 보호 화면이라고 단정하지 않습니다. OCR 모델은 실행 버튼을 활성화하기 전에 초기화합니다. 프레임이 1초를 초과하면 해당 좌표를 클릭하지 않고 새 화면으로 다시 인식합니다. 계속 느리면 찾는 버튼 주변으로 검색 영역을 줄이세요. 인식 테스트에서는 느린 결과도 확인할 수 있고 실제 터치는 하지 않습니다. 새 프레임 수신 실패는 인식 오류로 처리하며 3회 연속 실패하면 오류 안내와 함께 정지합니다.

오버레이 영역은 인식 및 클릭에서 제외됩니다. 0.5.0부터 헤더의 점 무늬 또는 제목 부분을 드래그해 대상 요소를 가리지 않는 위치로 옮길 수 있습니다. 마지막 위치를 저장하고 화면 가장자리 안으로 제한합니다. 이동 중 새 클릭을 보류하며 이동 전 인식 좌표를 그대로 사용하지 않습니다.

‘실행 로그’에서 결과·처리 시간·오류 코드·터치 전달 시각(`DELIVERED_AT_` 이후 단조 증가 ms)을 확인할 수 있습니다. 작업 성공 여부는 판정하지 않으며 로그는 앱 프로세스 종료 시 사라집니다.

## 0.2.0 업데이트

이전 버전을 삭제하지 않고 같은 debug 키로 서명된 새 APK를 덮어 설치합니다. 기존 매크로 설정과 기준 이미지는 유지됩니다. 패키지 설치 검사와 고정 게임 패키지 제한은 제거되었습니다. 실행/테스트 버튼에서 캡처에 동의하고 대상 앱으로 이동한 뒤 오버레이 버튼을 누르세요. 세션이 시작된 후 다른 앱으로 이동하면 자동 정지하며 다시 수동 시작해야 합니다.

## 0.3.0 업데이트

준비 중에는 오버레이의 실행·테스트·캡처 버튼이 비활성화됩니다. 준비가 완료되면 자동 활성화됩니다. ‘인식 테스트’에는 읽은 문구 목록과 정확히 일치/포함 조건이 함께 표시됩니다. 화면 원문과 OCR 문구는 실행 로그에 기록하지 않으며 테스트 화면 메모리에만 유지합니다. debug 빌드의 상태·결과·처리 시간·정지 이유는 단말기 Logcat의 `ScreenMacro` 태그로도 확인할 수 있습니다. 오류 정지 이유는 짧은 알림과 앱 상태 카드에 표시합니다.

초기 0.3.1은 비활성 상태바·접근성 버튼·현재 앱의 자식 창을 전체 차단하지 않고 가려진 영역만 제외합니다. 다른 앱 창·키보드·활성 시스템 창이 있으면 중단합니다.

## 여러 매크로 실행과 우선순위 (0.4.0)

1. 사용할 매크로를 저장하고 목록의 체크박스로 선택합니다. 기존 매크로는 업데이트 시 선택하지 않은 상태로 시작하며 자동 실행하지 않습니다.
2. 오른쪽 ☰를 잡고 위아래로 드래그합니다. 위에 있는 매크로가 우선입니다. 목록 끝에서 잠시 유지하면 자동 스크롤합니다. 손을 놓으면 순서를 저장하며 취소한 드래그는 저장하지 않습니다.
3. ‘선택한 매크로 실행 (N개)’ → 전체 화면 캡처 동의 → 대상 앱으로 이동 → 준비 완료 → ‘현재 앱에서 실행’을 누릅니다.
4. 매크로별 간격·클릭 전후 대기는 각각 적용됩니다. 상위 매크로가 기다리거나 조건이 없거나 후보가 여러 개면 다음 순위를 확인합니다. 대기 중인 상위 매크로를 기다리느라 전체 실행을 멈추지 않습니다.
5. 여러 조건이 함께 충족되고 클릭 가능한 경우 높은 우선순위부터 한 번 클릭합니다. 이후 새 화면에서 다시 인식합니다. 한 클릭으로 화면이 바뀌면 다른 매크로의 이전 좌표로 클릭하지 않습니다.
6. 오버레이·알림·앱의 ‘정지’로 전체 선택 그룹을 정지합니다. 같은 활성 앱·창을 대상으로 하며 다른 앱으로 전환하면 모두 정지합니다.

각 카드의 ‘시작’은 해당 매크로만 실행합니다. ‘인식 테스트’는 한 매크로씩 위치를 확인하며 실제 클릭하지 않습니다. 수정·삭제 후에도 지정한 순위를 유지하고 새 매크로는 목록 끝에 추가합니다.

상위 매크로가 매번 클릭 가능한 상태이면 우선순위 규칙에 따라 하위 클릭이 늦어질 수 있습니다. 여러 검색 영역·이미지 조건으로 인식이 1초를 넘으면 오래된 좌표로 클릭하지 않습니다. 버튼 주변으로 검색 영역을 줄이고 인식 테스트로 확인하세요.

## 밝기와 이동형 오버레이 (0.6.0)

준비 중에는 둥근 카드에 실행·정지 버튼이 표시됩니다. 게임에서 ‘현재 앱에서 실행’을 누르면 밝기를 최저로 낮추고 작은 카드로 접습니다. 실행 중 내부 감시 문구 대신 ASCII 스피너가 표시됩니다. 접힌 카드에는 ‘밝게’와 펼치기 버튼만 있고 ‘정지’는 펼친 카드에만 표시됩니다. 헤더 오른쪽 화살표나 제목을 누르면 펼치거나 접을 수 있습니다. 실행 중에도 헤더를 끌어 위치를 이동할 수 있습니다.

어두울 때 카드의 어느 부분이든 손을 대면 손가락을 떼기 전 즉시 기존 밝기를 복구하며 매크로는 계속 실행됩니다. 게임 화면의 카드 밖 터치는 밝기 복구 대상이 아닙니다. 복구한 밝기는 자동으로 낮아지지 않습니다. 펼친 카드에서 ‘어둡게’를 누르면 다시 최저 밝기로 전환하고 카드를 자동으로 접어 정지 버튼을 숨깁니다. 종료 시 그때 저장한 밝기·모드를 복구합니다. 어두운 상태의 밝기 버튼을 처음 터치하면 복구만 수행하며, 같은 터치가 다시 어둡게 만들지 않습니다. 밝기가 복구되면 접힌 카드에는 ‘밝음’이 표시됩니다. 오버레이의 정지 버튼은 펼친 뒤 사용하며 알림·앱의 정지도 유지됩니다.

정상 정지, 오류, 앱·창 전환, 화면 꺼짐·잠금, 캡처 종료, 접근성 해제 시 밝기를 복구합니다. 프로세스 강제 종료·전원 종료에서는 정리 코드를 실행할 수 없으므로 다음 앱 프로세스 시작 시 저장한 복구 기록을 처리합니다. 실행 중 시스템 설정 변경 권한을 취소하면 복구에 실패할 수 있습니다. 앱 상단에 안내가 남으며 권한을 다시 허용하고 앱으로 돌아오면 복구를 재시도합니다.

갤럭시의 게임 부스터 자동 터치 방지는 별도로 꺼둡니다. 최저 밝기 설정은 화면 잠금이나 터치 방지를 켜는 기능이 아닙니다. 게임이 자체 창 밝기를 강제하는 경우 시스템 밝기와 실제 출력이 다를 수 있어 해당 게임 화면에서 확인해야 합니다. [구현·검증 기록](BRIGHTNESS-OVERLAY.md)을 참고하세요.

## 검색 범위 UI (0.6.1)

새 매크로는 전체 화면 검색이 기본입니다. 숫자 좌표 입력은 제거했으며 편집 화면에서 ‘검색 범위: 전체 화면’ 또는 ‘검색 범위: 지정 영역’으로 현재 설정을 확인합니다. 기존 매크로의 지정 영역은 업데이트 후에도 보존합니다. 필요하면 ‘검색 범위 드래그 지정 (선택)’으로 화면을 캡처해 드래그로 범위를 선택합니다. ‘전체 화면으로 변경’을 누르면 제한을 없앨 수 있으며 ‘저장’을 눌러 적용합니다. 이미지 조건의 기준 이미지 자르기는 별도로 필요한 기능이며 계속 유지합니다.

## 알림 중 일시 대기 (0.6.2)

상단 알림 팝업이나 펼친 알림창이 보이면 실행 세션을 유지하고 새 클릭을 보류합니다. 알림이 사라진 뒤 같은 대상 앱·창을 확인하면 새 화면으로 다시 인식해 재개합니다. 개별 클릭 간격은 유지하며 클릭 전 대기는 새 인식부터 다시 적용합니다. 대기 중에도 사용자가 정지할 수 있습니다. 실제 다른 앱으로 이동하거나 화면이 잠기는 경우에는 기존처럼 종료하며 밝기를 복구합니다. 이미 Android에 전달한 제스처의 취소는 보장하지 않습니다. 상태바·내비게이션바만 보이는 정상 화면은 대기 대상으로 보지 않습니다.

0.6.3에서는 포커스를 갖지 않은 작은 접근성 버튼 등은 알림 대기로 취급하지 않습니다. 해당 버튼이 덮는 사각형에는 클릭하지 않습니다.

0.6.4에서는 높이가 큰 좁은 시스템 컨트롤도 전체 대기에서 제외하며 해당 사각형의 클릭 제외는 유지합니다.

## 0.7.0 이름·아이콘 및 권한 상태

앱·오버레이·실행 알림 이름은 AUTO입니다. 기존 패키지·데이터·권한·매크로 설정은 유지합니다. 사람(접근성), 종(알림), 해(밝기), 물음표(도움말) 순서로 한 줄에 표시합니다. 허용된 권한은 민트색, 미허용 권한은 회색에 빗금으로 표시합니다. 길게 누르면 항목과 상태를 확인할 수 있으며 TalkBack도 항목·상태를 읽습니다. 미허용 아이콘을 누르면 기존 설정 또는 권한 요청을 실행합니다. 실행 중 접근성·밝기 설정 잠금과 이미 허용한 알림 권한의 재요청 제한은 유지합니다. 도움말은 눌러 펼치거나 접습니다. 런처 테마 아이콘도 지원합니다.


## 키보드 대기·복귀 (0.7.1)

실행 중 대상 앱 위에 키보드가 보이면 오버레이와 캡처 세션을 유지하고 클릭을 대기합니다. 키보드를 닫고 같은 앱·창으로 돌아오면 새 프레임으로 인식하고 재개합니다. 클릭 전 대기는 다시 적용하고 매크로별 클릭 간격은 유지합니다. 키보드 대기는 인식 오류에 포함하지 않습니다. 화면 밖으로 이동한 키보드 창은 대기 조건에서 제외합니다.

다른 앱으로 바뀌면 종료하며, 키보드가 함께 떠 있어도 이 규칙은 유지합니다. 시작·인식 테스트·이미지 등록 시에는 먼저 키보드를 닫아야 합니다. 이미 전달된 터치의 취소는 보장하지 않습니다.


## 펼친 카드의 진단 안내 (0.8.0)

접힌 카드는 기존 스피너를 유지합니다. 헤더나 화살표로 펼치면 현재 상태, 매크로별 최근 후보 수·처리 시간·검사 시각을 확인할 수 있습니다. 최근 결과는 클릭 여부와 다릅니다. 후보 하나여도 우선순위·개별 간격·클릭 전 대기·결과 만료 때문에 클릭하지 않을 수 있습니다. 여러 조건을 함께 검사한 처리 시간은 그룹 전체 시간이며 개별 조건의 속도로 해석하지 않습니다. 검사하지 않은 매크로는 그렇게 표시하고, 대기 중에는 마지막 검사 시각을 확인하세요.

조건이 없으면 대상을 화면에서 확인하도록, 후보가 여러 개면 검색 영역을 좁히도록 안내합니다. 오래된 결과는 클릭 보류로 표시하고, 인식 처리 오류는 연속 횟수와 재시도 안내를 보여줍니다. 알림·키보드 대기 이유도 표시합니다. 상세 내용은 카드 안에서 스크롤할 수 있습니다.

오류·앱 전환·캡처 종료 등으로 세션이 중단되면 클릭과 캡처를 종료하고 밝기 복구를 시도한 뒤 ‘중단됨’ 안내 카드를 남깁니다. 자동으로 펼치지 않으며 직접 펼쳐 이유를 읽고 ‘닫기’를 누릅니다. 직접 ‘정지’를 누르거나 인식 테스트·등록이 완료되면 기존처럼 카드가 닫힙니다. 밝기 복구 실패는 종료 사유에 명시합니다.

마지막 예기치 않은 중단 사유와 시각은 앱 상단에도 보관합니다. 정상 정지는 이전 중단 사유를 덮어쓰지 않습니다. 실행 중 프로세스가 강제 종료되면 다음 앱 실행 시 ‘정상 종료되지 않음’을 표시하며 정확한 시스템 종료 원인을 추정해서 단정하지 않습니다. 접근성 해제·프로세스 종료 때 오버레이가 남는 것은 보장하지 않습니다.

진단 정보에는 화면 픽셀·OCR 원문·클릭 좌표를 추가로 보관하지 않습니다. 최근 검사 정보는 매크로마다 한 건, 영구 저장은 마지막 중단 한 건만 유지합니다.


## 인식 시간과 클릭 보류 구분 (0.8.1)

‘인식 942 ms’처럼 표시되는 값은 인식 처리에 걸린 시간입니다. ‘캡처 후 … ms’는 검사 완료 또는 클릭 보류 판정 시점에서 프레임을 받은 뒤 경과한 시간이며, 인식 외 창 검증 등의 시간이 포함됩니다. 현재 시간에 맞춰 증가하는 타이머는 아닙니다. 다중 매크로에서 인식 시간은 함께 검사한 그룹 전체 시간입니다.

미검출은 ‘조건을 찾지 못함’, 복수 후보는 ‘후보 N개’로 안내합니다. 오래된 결과라도 이 구분이 유지됩니다. 후보 1개를 검출했지만 캡처 후 1초가 지났을 때만 ‘후보 1개 검출 · 1초가 지나 클릭 보류’가 표시됩니다. 1초 제한은 변경하지 않았습니다. 여전히 느리면 해당 매크로의 검색 영역을 좁혀야 할 수 있습니다.

동일 프레임의 매크로별 창 검증을 묶고 터치 직전의 창·경계·가림 영역을 하나의 최신 조회로 확인합니다. 인식 정확도·우선순위·개별 간격은 유지하며, 실제 게임의 처리 시간 개선 정도는 재시험으로 확인해야 합니다.
