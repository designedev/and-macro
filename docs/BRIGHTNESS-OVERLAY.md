# 0.5.0 — 최저 밝기와 이동형 오버레이

검증일: 2026-10-03, Asia/Seoul. versionCode 6.

## 확정한 요구

사용자는 자동 터치 방지를 직접 끈 뒤 문제가 해결되었다고 확인했습니다. 새 요구는 실행 중 최저 밝기 → 종료 시 원상 복구, 드래그 가능한 오버레이, 디자인 개선입니다. 선택 질문에서 작은 둥근 카드와 실행 중 접기 방식을 확정했습니다. 준비 중에는 실행 버튼을 표시하고 실행 후에는 상태·정지만 남기며 펼치면 밝기 복구를 제공합니다. 헤더 드래그, 마지막 위치 저장과 화면 밖 이동 제한을 포함합니다.

## 밝기 제어

Android WRITE_SETTINGS 특별 접근 권한을 선언하고 앱별 시스템 설정 변경 화면으로 이동합니다. 권한이 없으면 실제 RUN 실행 전에 허용을 요청하며 거절 시 밝기를 변경하거나 매크로를 시작하지 않습니다. 캡처 동의는 별도로 유지합니다.

게임 화면에서 실행을 누르면 현재 SCREEN_BRIGHTNESS와 SCREEN_BRIGHTNESS_MODE를 읽어 앱 전용 SharedPreferences에 동기 commit한 뒤 수동 모드(0)·최저 밝기(1)를 적용합니다. 저장이 실패하면 시스템 설정을 변경하지 않습니다. 적용 도중 일부 쓰기가 실패하면 즉시 복구를 시도합니다. 인식 테스트·이미지 등록에서는 적용하지 않습니다.

모든 세션 종료 경로에서 원래 밝기를 먼저, 원래 모드를 다음으로 복구합니다. 두 쓰기와 복구 기록 제거가 성공할 때만 복구를 완료합니다. 기록 제거 또는 설정 쓰기가 실패하면 원본을 남겨 재시도할 수 있습니다. 자동 밝기 모드 복구 후에는 센서와 시스템 정책에 따라 밝기가 다시 바뀔 수 있습니다.

프로세스 강제 종료·전원 종료는 종료 콜백이 보장되지 않으므로 즉시 복구를 보장하지 않습니다. 다음 앱 프로세스 생성 또는 세션이 없는 앱 복귀 시 복구 기록을 처리합니다. 권한을 중간에 취소하면 실패 안내를 남기고, 다시 허용한 뒤 앱으로 돌아오면 복구합니다. 저장한 원래 값을 새 최저 밝기로 덮어쓰지 않습니다. 펼친 카드의 밝기 복구는 실행을 중단하지 않으며 이후 종료 복구는 중복 적용하지 않습니다.

이 방식은 화면을 검게 덮는 필터를 추가하지 않고 시스템의 출력 밝기 설정을 사용합니다. 기기의 하한, 게임 자체 창 밝기, 제조사 정책에 따라 실제 출력은 달라질 수 있습니다. 실기기의 게임 화면에서 최저 밝기 적용 및 종료 복구를 확인해야 합니다.

## 오버레이

- 불투명 남색 바탕, 둥근 모서리, 민트 실행 버튼, 분홍 정지 버튼, 이동 핸들, 상태 문구를 사용합니다.
- 준비 카드 폭 248dp, 실행 중 접힌 카드 폭 228dp. 자동 실행이나 자동 캡처 동의를 추가하지 않습니다.
- 헤더만 드래그 영역으로 사용하고 실행·정지·밝기 버튼은 독립 터치 영역으로 둡니다. 정지 버튼은 접힌 상태에서도 표시합니다.
- 시스템 바와 디스플레이 컷아웃을 고려해 위치를 제한하고 펼칠 때에도 다시 제한합니다. 취소한 드래그는 시작 위치로 되돌립니다. 마지막 완료 위치를 저장합니다. TalkBack 이동 동작도 제공합니다.
- 드래그 중 새 제스처를 전달하지 않습니다. 프레임의 오버레이 revision이 바뀌면 다시 인식하며 반복 이동을 연속 인식 오류로 세어 세션을 종료하지 않습니다. 최종 클릭 직전에도 revision·이동 중 여부와 현재 패널 범위를 확인합니다. 이미 Android에 전달된 제스처의 취소는 보장하지 않습니다.
- 자체 오버레이의 창 상태 이벤트는 게임 창 revision을 바꾸지 않습니다. 다른 앱·시스템 화면으로 전환되는 실제 창 검증은 유지합니다.

## 0.5.1 — 프레임 수신 시간 초과 복구

사용자는 0.5.0에서 인식 오류가 3회 발생한 뒤 앱이 종료된 것 같다고 보고했습니다. 자체 로그의 오류 간격은 각 4초이며, 마지막 정상 프레임 뒤 캡처 요청 3개가 제한 시간에 도달했습니다. 해당 시점 앱 프로세스는 살아 있었고, 매크로 세션 종료와 밝기 복구가 기록되었습니다. OCR 자체 실패보다 새 프레임 수신 중단으로 판단했습니다. 화면 밝기 변경이 직접 원인인지는 입증되지 않았습니다.

새 프레임을 500ms 동안 받지 못하면 기존 MediaProjection과 VirtualDisplay를 유지한 채 새 ImageReader의 Surface를 연결합니다. 기존 수신 큐를 닫고 최대 3.5초 동안 새 프레임을 기다립니다. 이전 비트맵을 재사용하거나 타임스탬프를 갱신하지 않습니다. 복구 실패는 FrameTimeoutException으로 기록하며, 실제 캡처 종료·3회 연속 오류 정지 및 밝기 복구 정책을 유지합니다. 캡처 작업 스레드의 로그 추가를 위해 런타임 로그 갱신도 동기화했습니다.

단위 테스트 58개와 Android 에뮬레이터 테스트 13개가 통과했습니다. 추가 단위 테스트 4개는 정상 수신, 무응답 복구, 복구 실패 시간 초과, 취소 후 복구 차단을 검증합니다. 추가 기기 테스트는 OWN_CONTENT_ONLY 가상 디스플레이의 정지된 합성 화면을 새 수신 표면에 연결했을 때 실제 이미지가 수신되는지 검증합니다. 이것은 실제 게임의 MediaProjection 미러링 성공을 대신하지 않으므로 실기기 재확인이 필요합니다.

증빙: `outputs/build-0.5.1.txt`, `outputs/emulator-static-frame-test.txt`, `outputs/emulator-frame-recovery-tests.txt`, `outputs/device-brightness-overlay-failure.txt`. 실제 단말기 화면 이미지와 OCR 원문은 수집하지 않았습니다.

## 0.6.0 — 확정한 추가 요구

0.5.1 실제 게임 동작은 사용자가 정상이라고 확인했습니다. 사용자는 감시 중 두 내부 문구를 ASCII 로딩 스피너로 바꾸고, 너무 어두운 화면을 쉽게 복구하도록 요청했습니다. 카드 터치 시 복구·항상 보이는 밝기 버튼 방식을 선택했으며, 정지를 잘못 누르지 않도록 실행 중 ‘정지’는 카드가 펼쳐졌을 때만 표시하도록 지시했습니다.

실행 중 label은 250ms마다 `| / - \`로 바뀌는 고정 폭 스피너입니다. 엔진 상태와 진단 로그는 그대로 유지하되 오버레이에는 내부 단계 문구를 표시하지 않습니다. 준비·테스트·오류 안내는 유지합니다. 숨길 때 스피너 콜백을 제거합니다.

카드 루트의 ACTION_DOWN에서 기존 밝기를 복구합니다. 버튼, 헤더, 빈 영역을 포함하고 게임으로 전달되는 카드 밖 터치는 감지하거나 차단하지 않습니다. 한 번 복구하면 자동 재감광하지 않습니다. 펼친 카드의 ‘어둡게’ 버튼만 실행 중 새 밝기 트랜잭션을 시작합니다. 복구 정보 영구 저장과 종료·오류 복구 정책은 유지합니다. 지연 게시되는 TextView 클릭에도 첫 터치가 복구 후 즉시 재감광하지 않도록 밝기 버튼의 터치 시작 의도를 보존합니다. 모든 카드 터치 중 새 제스처를 보류하고, 카드 밖 좌표에만 매크로 제스처를 전달합니다.

접힌 카드에 정지 버튼은 생성하지 않습니다. 펼친 상세 영역에만 정지를 유지하고 알림·앱의 정지는 유지합니다. 실기기 화면 및 OCR 원문은 수집하지 않습니다.

검증: 단위 테스트 58개, Android 에뮬레이터 테스트 14개 통과. 추가 UI 테스트는 실제 시스템 밝기 142→1→카드 ACTION_DOWN 즉시 142 복구, 터치 후에도 카드 유지, 자동 재감광 없음, 명시적 재감광과 첫 복구 터치의 지연 클릭 방지, 빈 상태 영역 터치 완료 후 클릭 보류 해제, 스피너 표시, 접힌 정지 버튼 제거를 확인합니다. 기존 이동·위치 저장·범위 제한 테스트도 통과했습니다. 검증은 Activity의 APPLICATION_PANEL에 같은 카드를 부착하며 게임 ACCESSIBILITY_OVERLAY는 실기기 확인이 필요합니다. 첫 에뮬레이터 부팅 때 System UI 응답 없음과 설치 완료 전 테스트 시작 실패가 있었고, 시스템 UI 재시작과 설치 완료 후 최종 전체 테스트를 통과했습니다. Lint는 0 errors, 24 warnings입니다.

## 0.6.1 — 다시 어둡게 하면 자동 접기
