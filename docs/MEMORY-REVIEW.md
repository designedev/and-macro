# 메모리 검토 및 최적화 — 0.6.5

2026-10-03. 기능·UI·인식 해상도·검출 주기·우선순위·클릭 간격·밝기·알림 정책을 유지하는 범위에서 검토했습니다. 추가 사용자 결정이 필요한 동작 변경은 적용하지 않았습니다.

## 발견 및 수정

| 부분 | 기존 위험 또는 비용 | 조치 |
| --- | --- | --- |
| 캡처 프레임 전달 | 생산자가 Deferred를 완료한 직후 소비자가 취소되면 반환 비트맵을 받지 못하고 명시적 recycle을 놓칠 수 있음 | ResourceHandoff로 소비자가 실제로 take하기 전까지 자원 소유권을 유지. 취소·늦은 생산은 즉시 회수, 성공한 전달 후에는 소비자가 회수 |
| 기준 이미지 읽기 | IO withContext에서 디코딩 후 원래 디스패처로 돌아갈 때 취소되면 결과 비트맵이 버려져 회수를 GC에 의존 | 동일한 소유권 전달 장치로 미전달 비트맵 회수 |
| 이미지 매칭 | 템플릿 검증과 실제 매칭에서 같은 PNG를 Mat로 두 번 변환하고 회색조 변환도 반복 | 실제 매칭의 회색조 Mat로 분산 검증까지 수행. 같은 임계값·매칭 알고리즘 유지 |
| OCR 시작 실패 | 한 recognizer가 시작된 후 다른 process 호출이 즉시 실패하면 이미 시작한 작업의 입력 비트맵이 일찍 회수될 수 있음 | 시작 결과를 각각 보관하고 시작에 성공한 양쪽 작업을 모두 기다린 다음 오류를 전달 |
| 실행 로그 | 매 기록마다 전체 리스트 복사 후 takeLast로 다시 복사 | 최대 1,000건의 독립된 불변 스냅샷을 한 번의 목록 작성으로 생성 |
| 창 진단 | 같은 창 정보라도 전체 문자열을 매 검사마다 만들고 이전 문자열과 비교 | 이미 만들어진 창 메타데이터 목록·콘텐츠 사각형을 먼저 비교하고 변경 때만 문자열 생성. 창 검사 결과도 재사용 |
| 오버레이 스피너 | 250ms마다 목록·문자열 생성 | 네 개 표시 문자열을 재사용. 같은 표시·주기 유지 |

발견한 비트맵 문제는 미전달 시 즉시 해제를 놓치는 경로이며, 그 자체가 무한히 도달 가능한 객체를 쌓는 누수라고 단정하지 않습니다. GC가 나중에 회수하더라도 반복 취소 시 피크 메모리와 회수 지연을 증가시킬 수 있습니다.

## 유지한 정상 자원 수명

- 캡처는 요청이 있을 때만 Bitmap을 만들고, 불필요한 Image는 use로 닫습니다. 인식용 프레임과 잘린 이미지는 finally에서 회수합니다. ImageReader/VirtualDisplay/MediaProjection/HandlerThread는 세션 종료 시 정리합니다.
- OpenCV Mat·점수 배열은 finally에서 release합니다. 한국어·영어 OCR 인스턴스는 세션 동안 재사용하고 실행 코루틴이 끝난 후 close합니다.
- OCR이 입력 픽셀을 사용할 수 있는 동안에는 취소되더라도 작업 완료까지 비트맵을 유지합니다. SDK 작업이 장시간 끝나지 않는 경우 일시적으로 세션 자원이 남을 수 있으나, 강제 해제로 읽기 도중 회수하는 변경은 하지 않았습니다.
- 편집 캡처·인식 테스트 미리보기는 각각 최대 한 장을 유지하며 기존 화면의 취소·복귀·활동 종료 경로에서 회수합니다. 보이는 미리보기를 메모리 경고만으로 강제 recycle하는 변경은 적용하지 않았습니다.
- 서비스 인스턴스는 종료 때 제거하며 오버레이 View와 스피너 콜백도 해제합니다. Repository/Room은 Application 수명으로 유지합니다.

## 메모리 규모와 제한

1080×2340 ARGB_8888 비트맵 한 장의 픽셀은 10,108,800바이트(약 9.64MiB)입니다. 패딩 처리·부분 영역 복사·캡처 그래픽 버퍼·OpenCV 화면/점수 행렬·양쪽 OCR 모델은 별도 메모리를 사용합니다. 따라서 총 사용량이 한 장 크기보다 상당히 큰 것은 가능하며, 총 PSS 한 시점만으로 누수를 판정할 수 없습니다. 큰 템플릿·전체 화면 검색·여러 서로 다른 OCR 검색 영역은 처리 중 피크를 증가시킬 수 있습니다. 동일 영역의 다중 문구는 이미 프레임별 OCR 결과를 공유하며 이미지 매크로는 순차 인식합니다.

정밀도나 기존 기능에 영향을 줄 수 있는 다운샘플링·한쪽 OCR 제거·검출 주기 변경은 하지 않았습니다. 세션에 무제한 템플릿 캐시나 비트맵 풀도 추가하지 않았습니다.

## 검증

- 단위 테스트 73개 통과: 취소 전/후 생산, 성공 전달, 디스패처 복귀 시 취소, 실제 두 스레드의 생산·취소 경쟁 100회에서 자원 해제 횟수 검증 포함.
- 전체 Android 테스트 17개 통과: 기존 OCR·이미지·창/알림·밝기·오버레이·드래그·저장 테스트와 새 로그 상한/스냅샷 독립성, Full HD 반복 이미지 인식 포함.
- 1920×1080 새 프레임 생성·이미지 인식·회수 40회, 매번 같은 고유 후보 좌표 검증. GC 요청 후 네이티브 할당은 10회 21,241,424바이트, 20회 21,241,424, 30회 21,239,872, 40회 21,239,424로 유지. Java 사용량은 약 4.8MB. 이 합성 이미지 시험 범위에서는 누적 증가가 관찰되지 않았습니다.
- 이 수치는 같은 프로세스의 할당량이며 전체 PSS나 실제 게임 OCR 전체 사용량이 아닙니다. allocator 캐시·GC 타이밍 영향을 받으므로 강제 바이트 상한 테스트로 쓰지 않았고, 변경 전후 절감률도 주장하지 않습니다.
