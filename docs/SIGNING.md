# APK 서명과 업데이트

사용자 결정에 따라 현재는 debug APK만 제작합니다. 새 개인 release 키를 생성하거나 사용자 기존 키를 사용하지 않았습니다. debug 서명은 Android 개발용 키이며 장기 업데이트에 사용할 개인 키로 간주하지 않습니다.

debug APK를 재빌드·업데이트하려면 같은 개발용 debug 키를 유지해야 합니다. 키 경로는 기본적으로 개발 PC의 `~/.android/debug.keystore`이며 저장소·산출물·보고서에 키나 비밀번호를 포함하지 않습니다.

개인용 release 배포를 시작할 때:

1. 사용자 소유 기존 키 사용 또는 새 개인 키 생성 방식을 결정합니다.
2. 키는 프로젝트 외부에 보관하고 암호화된 백업을 별도 보관합니다. 비밀번호는 패스워드 관리자에 보관합니다.
3. CI나 로컬 환경 변수로 서명 정보를 공급하고 Gradle의 release signingConfig를 연결합니다. 이 프로젝트의 release 빌드는 현재 서명 설정이 없습니다.
4. 버전 코드를 증가시키고 같은 개인 키로 업데이트합니다. 키가 달라지면 기존 설치에 덮어쓸 수 없습니다.
5. debug에서 다른 release 키로 전환하면 앱 삭제·재설치가 필요할 수 있습니다. 삭제하면 로컬 매크로와 기준 이미지도 삭제됩니다. 이번 범위에는 외부 가져오기·내보내기가 없습니다.

개인 키·비밀번호·서명 속성 파일은 Git이나 공유 보고서에 넣지 않습니다. `.gitignore`에서 jks/keystore/keystore.properties를 제외합니다.
